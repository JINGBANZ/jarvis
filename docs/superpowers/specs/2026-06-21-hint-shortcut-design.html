On-demand hint shortcut — one round trip

Press ⌥⌘J → screenshot + a synthetic “give me a hint” message go to the brain in one call → a hint appears on the overlay.

Problem

A screen-aware hint costs two brain round trips today. The model has no eyes until it calls the capture_screen tool, so the loop is: trigger → model asks for a screenshot → CoachDriver captures and re-injects it → model reasons again and finally speaks. That second trip is pure latency, and it only fires reactively (when audio triggers a turn).

We want a deliberate, user-initiated way to get a hint right now in one trip: press a global key, the app grabs the screenshot itself, injects it plus a synthetic hint request into the first request, and forces the model to speak.

Why this is one trip instead of two

Decisions

QuestionDecision
When active?Only while a session is running. Reuses the live brain client, server-side conversation, and rolling transcript so the hint has full context. If stopped, the keypress is ignored with an NSSound.beep().
Hotkey mechanismRaw Carbon RegisterEventHotKey (no dependency). The one global-shortcut API Apple never modernized → no Accessibility/TCC permission, no dialog, and it builds under the Command Line Tools.
Customizable?No — fixed ⌥⌘J for now. A rebinding UI is deferred; the value is the one-trip hint, not the binding control.
Synthetic messageFixed generic prompt (hard-coded, not configurable).
Force a reply?Yes — force the speak tool (ToolChoice.force("speak")) so a keypress always yields a visible hint.
Why not the KeyboardShortcuts package? It was the first choice (industry standard, free recorder UI), but every modern release uses SwiftUI macros (@Entry in 3.x, #Preview in 2.x) whose plugins ship only with full Xcode. Jarvis builds CLT-only (verified: xcode-select -p is /Library/Developer/CommandLineTools), so the package fails to compile here regardless of version. Raw Carbon needs no macros and no dependency, with the identical permission profile.

Architecture

Three changes. The one-trip mechanic lives in JarvisCore (testable); the hotkey is OS glue in JarvisApp.

1 · New trigger .manualHint — Triggers/Trigger.swift

Add a case to TriggerReason and a promptLine (the fixed synthetic message) to TriggerContext. The enum is Equatable/Sendable; the existing if case .silence switch is non-exhaustive, so nothing else breaks.

case manualHint   // user pressed the hint hotkey — capture + force a hint, one trip

2 · Direct injection + forced speak — Coach/CoachDriver.swift

In runTurn(_:), after the base convo is built and before the tool loop:

if reason == .manualHint {
    let screen = self.screen
    let img = await Task.detached(priority: .userInitiated) { screen.capture() }.value
    if Task.isCancelled { return .cancelled }
    if let img { convo.append(.userImage(img)) }   // else: hint from context alone
}
let turnToolChoice: ToolChoice = (reason == .manualHint) ? .force(speakTool.name) : .auto
// ... brain.respond(messages: convo, tools: coachTools, toolChoice: turnToolChoice, ...)

Forcing speak means the model can’t call capture_screen (image already attached) and must return a hint on the first iteration. Conversation continuity, prior-close bundling, coalescing, and Stop-cancellation all keep working — .manualHint flows through the same path.

The system prompt’s “you cannot see the screen unless you call capture_screen” stays true for audio turns. For a manual hint the image is provided directly as an input_image and speak is forced, so the model answers from what it sees. No prompt change.

3 · Global hotkey — Shortcuts/HotkeyController.swift

A thin @MainActor type that registers ⌥⌘J via Carbon and exposes an onRequestHint callback, mirroring MenuBarController’s onStart/onStop.

  • InstallEventHandler(GetApplicationEventTarget(), …) for kEventHotKeyPressed. The C callback can’t capture context, so self is passed via userData and recovered with Unmanaged; Carbon delivers on the main thread, so it uses MainActor.assumeIsolated { controller.onRequestHint?() }.
  • RegisterEventHotKey(UInt32(kVK_ANSI_J), UInt32(cmdKey | optionKey), …).
  • No deinit teardown: app-lifetime object (like the menu bar / overlay); the OS reclaims the registration on exit. (A deinit couldn’t touch the non-Sendable Carbon pointers under Swift 6 anyway.)

4 · Wiring — App/AppDelegate.swift

hotkeys = HotkeyController()
hotkeys?.onRequestHint = { [weak self] in
    guard let self, let fire = self.requestManualHint else { NSSound.beep(); return }  // no session
    fire()
}

Instead of storing the driver, AppDelegate stores a requestManualHint closure capturing the Sendable driver + turn box (the same trick the transcriber callbacks use). It’s set in start(), cleared in stop() — non-nil only while running, so the guard enforces “only during a session,” and routing through TurnTaskBox gives coalescing + Stop-cancellation for free.

5 · No new dependency, no Settings UI

Carbon is in the SDK — Package.swift and build-app.sh are unchanged, and JarvisCore stays Foundation-only (the Carbon import lives in the single HotkeyController.swift). The binding is fixed, so there’s no Settings section in this scope.

Data flow

Error handling / edge cases

  • No session running — guard ignores the press; NSSound.beep() signals it.
  • Screenshot fails (capture() → nil) — proceed without the image; forced speak still produces a hint from transcript/conversation context.
  • Stop mid-capture — the post-capture Task.isCancelled guard returns .cancelled before any overlay render.
  • Rapid double-press — TurnTaskBox + claimOrPend coalesce into one pending follow-up turn, like audio triggers.
  • Hotkey conflict — if the system/another app owns ⌥⌘J, RegisterEventHotKey fails and it won’t fire; ⌥⌘J is uncommon, and a rebinding UI is the deferred follow-up.

App — smoke checklist

  • ⌥⌘J fires globally (even when another app is frontmost) and shows a hint while running.
  • Beeps when stopped.
  • JarvisApp is not unit-tested (per CLAUDE.md). App bundles + signs cleanly.

Out of scope (YAGNI)

  • Configurable hint prompt text (fixed for now).
  • A rebinding UI for the shortcut (fixed ⌥⌘J — a recorder or preset dropdown can come later).
  • Working without a session (auto-start / one-shot no-context path).
  • Additional shortcuts beyond the hint trigger.
