# Security Policy

Jarvis is pre-1.0 experimental software. Only the current `main` branch receives security fixes;
there are no supported release lines yet.

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/JINGBANZ/jarvis/security/advisories/new)
to report a vulnerability. Do not include vulnerability details, credentials, session artifacts, or
captured audio/screen content in a public issue or pull request. If the private form is unavailable,
open a detail-free issue asking the maintainer to establish a private contact channel.

Include the affected commit or version, impact, reproduction steps using non-sensitive fixtures, and
any suggested mitigation. Reports involving credential exposure, unintended filesystem access,
audio/screen persistence or egress, ghost-mode disclosure, unsafe local-agent execution, or GitHub
Actions trust boundaries are especially useful.

The maintainer will acknowledge and triage reports as availability permits. This project does not
currently promise a response or remediation SLA.
