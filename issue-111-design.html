A trustworthy action boundary for every Jarvis brain.

Add a Foundation-only coaching action broker first, then expose it to Claude Code and Codex through one private MCP sidecar. MCP is the adapter; the broker remains the security, lifecycle, and exactly-once boundary.

Review scope Implemented architecture, invariants, and comparison evidence.
Implementation status Implemented in the issue worktree; 546-test serialized gate is green.
Comparison conclusion Better action continuity; no proof of greater model intelligence.

01 / DECISION

Broker first. MCP second.

Do not make the sidecar itself authoritative. Every action—OpenAI native tool call, or CLI MCP request—must enter the same per-attempt state machine before Jarvis captures, speaks, records silence, or commits history.

Core boundary

One typed action protocol

capture_screen, speak, and stay_silent have one schema, one ordering rule, and one failure taxonomy in JarvisCore.

Transport adapter

A deliberately small MCP server

The sidecar performs MCP lifecycle and translation only. It cannot capture the screen, touch Activity, present UI, run shell commands, or commit a tip.

Commit boundary

Effects happen after clean completion

Terminal actions are staged. CoachDriver commits exactly once only when the provider completed cleanly and the attempt revision still wins.

Design thesis MCP standardizes how the local agent calls Jarvis. It does not, by itself, make those calls safe. Safety comes from an opaque attempt capability, a broker-owned state machine, provider isolation, cancellation, and a single host commit point.
02 / BENEFIT

Why issue #111 is worth addressing.

The biggest benefit is not “using an industry standard.” It is making a provider response incapable of bypassing Jarvis’s attempt lifecycle.

Guaranteed by design 1 boundary

Fewer stale and duplicate effects

A cancelled turn, old provider, replayed request, second terminal call, or response from a prior configuration cannot produce a late tip or a second silence record.

Guaranteed by design 3 tools

A much smaller agent capability surface

Jarvis advertises only its coaching actions and rejects inherited MCP servers and unrelated built-ins. Effects remain behind the host instead of inside an agent.

Guaranteed by design 0 parsers

Remove prompt-JSON actions from CLI coaching

Claude and Codex no longer need separate tolerance rules for prose, fences, flattened arguments, or malformed action JSON. A toolful direct CLI call is rejected before a provider process starts.

Expected; benchmark 1 agent run

Cheaper capture loops for local agents

Today a CLI capture causes another full respond and another process. MCP lets one agent process call capture, receive image/OCR, and continue. The latency and token win must be measured with issue #110’s benchmark.

Operational typed

Cleaner Activity and diagnostics

Activity gets only committed actions and fixed protocol-failure copy. Raw MCP frames, capability checks, timings, and provider errors stay redacted in jarvis-debug.log.

Foundation portable

A testable base for issue #110

Warm runtimes can be leased and bound to fresh attempt capabilities without moving policy into provider processes. Pooling changes readiness, not action authority.

Honest limit This does add a sidecar, IPC, packaging, and process-lifecycle surface. It is justified only if the broker stays small and the provider adapters fail closed. MCP must not grow into a plugin platform or generic tool registry.

04 / ARCHITECTURE

One broker, every action path.

Local agents call through MCP. The OpenAI API continues using native function calls. Those two paths converge before any Jarvis action is accepted. An MCP-incompatible CLI is unavailable rather than downgraded to another action protocol.

Why a bridge library target

JarvisMCPBridge is the narrow POSIX edge shared by the app host and the sidecar. It owns framing, Unix sockets, authentication handshake, and redaction—but no coaching policy. The second executable is the concrete compiler-boundary trigger allowed by the repository’s target rules.

Why the broker stays in Core

The state machine is transport-neutral and Foundation-only. Tests can submit actions without starting a process, opening a socket, importing AppKit, or depending on an installed provider CLI.

05 / PROTOCOL

The broker owns the attempt state machine.

A provider may capture serially zero or more times, then stage one terminal decision. Anything else poisons that attempt with a typed protocol failure.

Current state Input Next state Result
Open capture_screen({}) Open Capture once; return image + OCR after current-attempt recheck.
Open speak(lines) Terminal staged Validate nonblank bounded lines; do not render yet.
Open stay_silent({}) Terminal staged Stage silence; do not record yet.
Open Provider completes Protocol failed Typed missingTerminal.
Terminal staged Any further action Protocol failed Duplicate/conflicting terminal or capture-after-terminal.
Any live state Malformed, unknown, concurrent, stale, or replayed call Protocol failed Revoke attempt; raw detail stays diagnostic-only.
Terminal staged Clean provider completion + current revision Committed Return one commit token and one terminal decision.
Any uncommitted state Cancel, timeout, Stop, retry, or revision loss Invalidated Discard terminal; reject all later calls.

Idempotency versus replay

A transport retry with the same authenticated connection, bridge request ID, MCP call ID, and identical payload returns the cached result; it never recaptures or restages. Reusing a call ID with a new request or changed payload is semantic replay and fails the attempt.

Multiple calls in one native response

Reject the response as ambiguous. In particular, accepting [capture_screen, speak] would let the terminal decision precede the capture result it supposedly uses. Native providers must return one action per model response; MCP agents naturally call tools serially.

Linearization point CoachDriver checks the attempt identity and configuration revision under its existing state lock, marks the attempt committed, and receives the broker’s one-shot commit token. A Settings edit or Stop that wins the lock first invalidates the effect; a commit that wins first defines the completed attempt boundary.
06 / SECURITY

Authenticated runtime, fresh attempt binding.

Design the sidecar handshake so it works for today’s one-shot processes and tomorrow’s warm runtime pool without putting an attempt secret in process arguments.

Start one short session socket

The host listens at <session>/mcp.sock. The short basename protects against macOS Unix-socket path limits. The containing session directory is already 0700.

Authenticate a sidecar once

Create a 0600 bootstrap ticket containing 256 random bits. Provider config passes only its path. The sidecar authenticates over the socket; host and sidecar delete/zero the one-use ticket immediately.

Bind the runtime to a fresh attempt in memory

Before model work begins, the host sends attempt ID, configuration revision, action policy, and a fresh attempt capability across the authenticated bridge. Nothing secret is added to the model prompt or CLI argv.

Validate every call twice

The bridge validates connection, sequence, frame size, and binding. The Core broker validates capability, attempt/revision, schema, ordering, idempotency, and replay. Unknown tools are forwarded to the broker, not silently filtered.

Revoke before teardown

Stop/revision/cancellation first invalidates the attempt, then closes the bridge and provider runtime. The sidecar exits on host disconnect or MCP stdin EOF; the runner also terminates the owned process group.

No effect authority

The sidecar cannot import AppKit or call Activity. It has only stdio, its private host socket, Foundation/POSIX parsing, and stderr for already-redacted diagnostics.

No sensitive logging

MCP frames are summarized by method, tool, byte count, result, and timing. Capability bytes and image/OCR payloads are never logged. Activity receives no raw failure text.

No broad IPC listener

Unix-domain socket only; no TCP/HTTP port, Bonjour, browser, OAuth, or network listener. The socket never leaves the owner-only session directory.

Threat-model boundary 0700/0600 protects against other local users, not a malicious process already running as the same macOS account. The random ticket prevents accidental and stale cross-session use; it is not a sandbox between same-UID hostile processes. Jarvis’s documented restricted-account/App Sandbox path remains the stronger boundary.
07 / PROVIDERS

Capability-gated adapters, not optimistic flags.

“CLI supports MCP” is insufficient. Native MCP mode is enabled only when the installed version proves isolation, persistence suppression, image input, cancellation, and clean completion together.

Conformance profile

  • Exact per-run MCP config
  • User/project settings isolation
  • Exact MCP tool allowlist
  • Built-in tool suppression
  • No provider session persistence
  • Image input inside the active turn
  • Bounded cancellation and process-tree teardown
  • Model/effort selection
  • Machine-readable clean completion
Failure of any required item marks that target unavailable. It never silently widens the provider’s tools or changes action transport.

OpenAI API — native calls, same broker

Do not wrap the Responses API in MCP. Keep native strict function calls and provider linkage, but submit every returned action to the broker. This satisfies “CoachDriver consumes terminal decisions only through the broker” without replacing a stronger native interface.

Manual hints use the same MCP contract A local-CLI manual hint forces the speak MCP tool. Final prose is not converted into a tip. A text-only exit, runtime MCP error, rejected action, stale attempt, or malformed call fails closed with no overlay.
08 / LIFECYCLE

Attempt and runtime lifetimes stay separate.

This is the coordination point with issue #110: a runtime may be warm and reusable, but every lease receives a fresh capability and clean client-managed context.

Snapshot

CoachDriver chooses one immutable route target and creates attemptID + configurationRevision + actionPolicy. This revision includes provider, model, effort, credentials, Stop→Start generation, and route topology.

Bind

A one-shot or warm provider runtime is bound to that attempt. The broker opens in open; a summarizer receives no action attempt and no MCP server.

Run

MCP capture calls round-trip inside the same provider run. Native OpenAI captures continue through the existing client-managed tool loop, now broker-validated.

Finish

A clean provider exit is necessary but not sufficient. The broker must hold exactly one terminal decision and no protocol failure. Incomplete/truncated completion invalidates it.

Commit or discard

The current revision commits once; any other outcome discards. A warm runtime is unbound and either retired or returned only after its cleanliness contract passes.

Settings behavior change

Effort edits keep the in-flight attempt’s snapshot valid and apply to the next attempt, preserving the existing route-health contract. Stop, cancellation, or a superseding attempt invalidates the old broker before it can commit.

Failure and route behavior

A protocol failure is a failed attempt on its snapshotted target. It enters the existing route-health policy; Jarvis never switches provider inside that attempt. Pending work starts fresh with the newest finalized transcript.

11 / ROLLOUT

Land safety before transport.

Each phase is independently reviewable and fails closed. No phase requires adopting ACP or waiting for the warm pool.

Broker current behavior

Add the Core broker, route OpenAI native calls through it, and cover every invalid transition and race before switching local agents to MCP.

Build the sidecar and bridge

Implement protocol/IPC with fake-host integration tests. Bundle and sign the helper, but do not enable it for providers yet.

Enable Claude MCP behind conformance

Require exact tool discovery, action flow, persistence suppression, cancellation, and ghost-mode smokes; delete prompt-shaped coaching actions.

Enable Codex MCP behind the stricter gate

Ship only for versions where unrelated tools are demonstrably absent. Otherwise mark that CLI target unavailable and record the capability reason in debug.

Connect issue #110

Warm pools lease already-authenticated runtimes and use bridge bind/unbind for a fresh attempt capability. Compare cold/warm text and capture paths with #110’s p50/p95 and resource benchmark.

MCP-only decision Jarvis is in active development, so there is no released CLI action compatibility contract to preserve. Unsupported CLI versions are unavailable; helper/bootstrap defects remain visible failures instead of selecting a second protocol.
12 / REVIEW

Decisions applied by the implementation.

These choices are now concrete review points and can still be changed before merge.

1

Broker every provider, not only CLI MCP requests?

Recommend yes. Otherwise CoachDriver still has more than one action authority and the acceptance criterion is only partially true.

2

Add a dedicated JarvisMCPBridge target?

Recommend yes. The app and second executable share an OS-bound transport that should be compiler-separated from Foundation-only policy.

3

Make model and effort edits invalidate the in-flight attempt?

Implemented no for effort-only edits. The existing attempt keeps its snapshotted configuration; the new effort applies to the next attempt. Stop, cancellation, or a genuinely replaced attempt invalidates the old broker.

4

Fail Codex native MCP closed unless built-ins are proven absent?

Recommend yes. Read-only sandboxing is not equivalent to “only three tools”; an agent could still read files or spend turns on unrelated tools.

5

Use one generic Activity event for action-protocol failures?

Recommend yes. Suggested fixed copy: “⚠️ coaching action was rejected this turn — listening continues.” Provider, tool, frame, validation, and replay detail remain only in debug.

Explicitly out of scope
No ACP, generic MCP host, user extensions, third-party tools, remote MCP transport, browser/network/shell capability, new UI, permission prompts, or provider switching inside an attempt.
